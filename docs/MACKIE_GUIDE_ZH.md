# Windows Fader Bridge for Mackie Control — 中文研究版指南

这是独立的 **Mackie Control / MCU 版**，不是 P1-Nano 专用驱动，也不是
EUCON 版的替代更新。P1-Nano 是首个计划验证的设备，其他采用标准 MCU
报文的设备使用同一个协议核心。

目前完成了程序、协议测试和真实 Windows 音频会话测试，**尚未完成实机
联调**。能够打开 MIDI 端口，不等于电机、屏幕和所有按键已经验证。

## 1. 要安装什么？

使用环境：Windows 11 x64、控制器处于 MCU 模式、可用的 MIDI 输入和输出。
构建需要 Visual Studio 2022 的 C++ v143 工具链与 Windows SDK。
Mackie 版不需要 Avid SDK、EuControl、NAudio、虚拟 MIDI 线或第三方 MIDI 库。
运行编译好的程序还需要 Microsoft Visual C++ x64 运行库；开发机已具备。

本次开发机器已具备编译环境，Windows 也已识别 P1-Nano 的四组 MIDI 端口，
iMAP 已安装，因此**暂时不需要安装新软件**。官方手册和备用安装 ZIP
保存在本机 Documents 下的 `Windows Fader Bridge Private Research/Mackie Control`，
没有运行安装包、刷新固件或修改设备设置。

其他设备是否需要厂商 USB 驱动，按该设备官方说明操作。不要把本机
P1-Nano 的安装情况套用到所有 MCU 控制器上。

## 2. 构建和启动

在仓库目录执行：

```powershell
.\scripts\build-mackie.ps1
```

生成：`artifacts\mackie\Release\WindowsFaderBridge.Mackie.exe`。
双击启动。这是独立进程、独立托盘、独立配置，不会停止现有 EUCON 版。

程序每次启动都处于 **MIDI 未连接**。这是研究阶段的安全设计，不会
根据设备名称自动打开端口，也不会自动把电机推到某个位置。

1. 控制器选择 MCU / Mackie Control 模式，不是 HUI。
2. 在程序选择对应的 MIDI 输入、输出；输入是设备发给电脑，输出是电脑发给设备。
3. 普通设备保留“通用 Mackie Control”。P1-Nano 可选其配置项；两者使用同一套报文。
4. 保留“触摸保护”，再点“连接设备”。电机会开始同步当前 Windows 音量。
5. 关闭窗口会隐藏到托盘；真正退出请点“退出”或托盘菜单里的退出。

不要让 DAW 和本程序同时争用同一对控制端口。不确定某个端口用途时，不要连接。

## 3. P1-Nano 特别说明

P1-Nano 的单根物理推子代表 8 个虚拟通道及 Master，不能理解成软件只能
控制一个应用。控制器自身的通道选择与本程序的 MCU 分页共同决定目标。

| 设备上的 DAW 层 | 输入 | 输出 |
| --- | --- | --- |
| DAW 1 | `iCON P1-Nano` | `iCON P1-Nano` |
| DAW 2 | `MIDIIN2 (iCON P1-Nano)` | `MIDIOUT2 (iCON P1-Nano)` |
| DAW 3 | `MIDIIN3 (iCON P1-Nano)` | `MIDIOUT3 (iCON P1-Nano)` |
| 第 4 组端口 | iMAP / 维护用途 | 本程序拒绝连接 |

名称以 Windows 实际显示为准；括号外程序添加的数字只是本次枚举编号，
不会被当作设备身份永久依赖。端口编号、名字可能随驱动、固件变化。

请先在 iMAP 保存自己的配置，再选择适合 MCU 的 DAW 模式，例如官方手册
所列 Cubase / Bitwig 工作流。不要为试验覆盖已有自定义页面。
如需 iMAP 转发触摸屏映射，应先连接控制器并启动 iMAP，再启动本程序。

官方固件说明提到 1.24 修复过“选中通道和推子对应不一致”。本次**没有核实
你机器的固件版本，也没有升级**；如果后续发生类似问题，再查看版本。
不要只从 USB 名字推断固件版本。

依据：[P1-Nano 官方说明书](https://s3.amazonaws.com/assets.iconproaudio.com/wp-content/uploads/2023/07/01050723/P1Nano-PD3V102-English.pdf)，
[官方固件记录](https://s3.amazonaws.com/assets.iconproaudio.com/wp-content/uploads/2023/07/10071915/P1-Nano-Firmware-Release-Notes-4.html)。

## 4. 默认控制逻辑

| MCU 控件 | Windows 行为 |
| --- | --- |
| 通道推子 | 当前应用或音频设备的音量 |
| Master 推子 | 当前系统默认输出的音量 |
| V-Pot 旋钮 | 支持立体声平衡的通道调 Pan / Balance |
| 按下 V-Pot | Pan 回到 Center |
| Track 分配键 | 旋钮改为 Volume |
| Pan 分配键 | 旋钮恢复为 Pan |
| Flip | Pan 模式下互换推子和旋钮的音量 / 平衡职责 |
| Mute | 切换当前通道静音，LED 跟随 Windows |
| Solo | 仅应用通道：使其他应用静音；再按恢复 |
| 全局 Solo / Clear Solo 命令 | 清除本程序管理的 Solo，恢复之前的静音状态 |
| Rec | 仅设备通道：选择为对应的默认输入或输出，不是录音开关 |
| Rec LED | 该设备确实是默认设备才亮 |
| Select | 选中通道；应用通道尝试恢复窗口并置于前台 |
| Bank 左右 | 每次翻 8 个逻辑位置 |
| Channel 左右 | 每次移动 1 个逻辑位置 |
| Play / Stop | 所选应用播放暂停 / 停止；无法停止时尝试暂停 |
| Rewind / Fast Forward | 上一首 / 下一首 |
| Jog | 播放器允许时相对调整进度 |
| Cycle | 播放器允许时切换循环 |

以上按标准 MCU 按键编号识别。设备印刷名称或 DAW 模板不同，实际发出的
编号也可能不同，需要对照 MIDI 日志。未对应的硬件键可以学习分配命令。
Transport Record 暂不代表 Windows 录音，不会自动开始录音。

### 通道与分页

停用或无法打开的端点不加入；可用但非默认的输入设备仍可显示电平。
应用和设备以稳定 ID 保留位置，退出应用不会让后面通道突然前移。
重新出现时返回原位置。超过 8 个位置可翻页；窗口列表可滚动查看全部。
当前音频层上限是 128 个同时存在的音频槽位，不是某台设备的推子数量。

如历史离线空位过多，先断开 MIDI，再点“清理离线空位”。这会改变后续
位置编号，但不会改变音量。输入设备成为默认设备只改变 LED，不交换通道。
Master 的专用推子跟随默认输出；设备原有逻辑通道仍留在原位。

### 触摸保护

触摸推子期间不向该电机发送位置，也不允许切页、Flip 或改变选中通道。
松手后按 Windows 状态同步。默认忽略没有触摸消息的推子输入，以防电机
反馈被误认为人手输入。

只有确认设备没有触摸消息、且不会回传电机动作时，才关闭“触摸保护”。
关闭后抗反馈能力降低，出现抖动应立即断开；不要直接给所有设备关闭。

### 显示、媒体和高级音频

- Windows 窗口保留完整中文名称；标准 MCU LCD 只能显示短 ASCII 文本，
  当前每个通道 6 个字符加间隔，不能承诺中文或自定义字体。
- 峰值取 Windows 实际音频通道的最大值，转换成 MCU 的 13 档显示。
  不等同于 EUCON 的分声道立体声峰值表，也不是插值真峰值检测。
- MCU 标准反馈不等于每台设备都会自动启用电平显示。厂商特有的显示初始化、
  RGB、D5 和触摸屏文字暂不发送，不能把“TX 增加”当成屏幕已验证。
- 选中应用后，窗口显示其可读取的歌曲名、艺术家、进度和播放状态。
  只能读进度但不能拖动的应用显示“只读”。不提供能力的动作不会伪造成功。
- 没有媒体会话的旧播放器可尝试系统媒体键；这是全局后备路径，可能由另一个
  播放器接收，不能保证专门控制 foobar2000。
- 列表选中应用后，可从“所选应用输出 / 输入”改变该应用路由，或恢复
  “跟随系统默认”。这是应用路由，不会修改系统默认设备。应用可能需要重启播放。

## 5. 自由分配 186 个 Windows 命令

命令覆盖 14 个分类：音频、系统工具、设置、个人文件夹、文件管理器、窗口、
虚拟桌面、任务栏、编辑、浏览器、媒体、截图输入、输入法和辅助功能。
完整的英文名、中文解释见 [Windows 命令中文手册](WINDOWS_COMMANDS_ZH.md)。
该手册的“命令说明”通用，EuControl 分配步骤只适用于 EUCON 版。

分配方式：

1. 在本程序选分类及命令，例如 `System Tools → Task Manager`。
2. 点“学习按键”，然后按控制器上的目标按键。
3. 学习成功会列出 MIDI 通道、Note 编号和命令；**这次学习不执行命令**。
4. 松开后再次按下才执行。重复分配同一按键会替换原命令。
5. 可在列表选中一条后取消分配，恢复该按键原有的 MCU 行为。

为保护核心操作，MIDI 通道 1 的推子触摸、通道按键和分页键不能覆盖。
可学习该通道 Note 54–103 的功能键，或 MIDI 通道 2–16 的 Note 按键。
只支持按下 / 松开式 Note；CC、只有按下没有松开的宏、QWERTY 不是这套学习输入。

`Mono Audio` 和 `Clear Solo` 的灯按实际状态显示；普通 Windows 命令的灯
随按下 / 松开，不代表目标应用的内部状态。Ctrl / Alt 等单独保持型修饰键
不是当前命令模式；组合快捷键作为一次完整命令发送。

### P1-Nano 的 80 个触摸屏位置

触摸屏的页面、标签和颜色由 iMAP 管理。本程序**不写 iCON 私有触摸屏协议**。
建议在 iMAP 中使用独立的 MIDI 通道 16，按下发 Note On，松开发 Note Off，
5 页依次使用 Note 0–79；再在本程序学习对应命令。这里的通道 16 是 MIDI
消息通道，不是 USB 第 4 端口。

提供 [80 键建议表](mackie-touchscreen-example.csv)，可按“系统、窗口、文件、
媒体、编辑”五页安排。它只是项目自编的配置参考，不是 iMAP 导入文件，
不包含厂商预设。其他具有 MIDI 自定义键的 MCU 设备同样可以采用这张表。

QWERTY 热键也能由 iMAP 直接发给 Windows，但它们不会经过本程序的命令
学习和状态反馈，两种方式不要对同一个按键重复使用。

## 6. 配置、日志与恢复

- 配置：`%LOCALAPPDATA%\Windows Fader Bridge\Mackie\settings.txt`。
- 诊断：程序旁的 `FaderBridge.trace.log`，点击“诊断目录”打开。
- “MIDI 日志”开启后记录输入、输出和错误；关闭可减少日志量。
- 配置只存端口名称、显示选项、稳定通道顺序及命令 ID，不允许任意脚本路径。
- 端口变化或发送失败会断开，不自动改连另一台设备；请刷新、重新确认后连接。
- 断开不会替你修改 Windows 音量，也不会自动取消其他程序设置的静音。
- 退出前有 Solo 时，建议先执行 Clear Solo。本阶段不要在 EUCON 和 Mackie
  两个进程中同时管理 Solo，它们还没有统一跨进程的 Solo 所有权。

## 7. 验证命令和实机清单

常规构建会运行纯协议 / 配置 / 身份队列测试，不打开 MIDI 或音频端口：

```powershell
.\scripts\build-mackie.ps1
```

显式运行真实音频集成测试：

```powershell
.\scripts\build-mackie.ps1 -AudioIntegration
```

它只创建并调整自身的无声、非持久化音频会话，不碰系统默认设备、Mono、
其他应用的 Solo / Mute 或硬件 MIDI。现有控制程序可能短暂看到这个测试通道。

程序还支持 `--smoke-test`：后台运行约 6 秒，读取音频和端口后退出，
MIDI 发送数必须为 0；活动音频端点不存在的机器会报告失败。

回来后的实机验证顺序：

1. 保存 iMAP 配置，确认 MCU 模式和匹配端口。
2. 先看 RX 是否随操作增加，测试一个应用推子和反向 Windows 音量。
3. 验证触摸、松手、快速反转；电机无来回争抢。
4. 验证 Select、Mute、Solo、Rec 默认输入 / 输出及 LED。
5. 开 9 个以上逻辑通道，确认翻页、退出应用、再出现后不串道。
6. 验证 Master 默认输出切换、Pan 及按下回中。
7. 检查 LCD、峰值、播放键、歌曲状态和一个学习的 Windows 命令。
8. 最后检查断线 / 重连、托盘后台、重新启动后配置恢复。

需要另一台标准 MCU 设备完成交叉验证，才能扩大“已验证兼容”名单。
目前不支持 HUI、MCU Extender 多机拼接、旧 Logic Control 型号握手、
自动重连 / 开机连接、安装器或完整通道重排 UI。

协议依据和未验证项详见 [研究记录](MACKIE_RESEARCH.md)。
