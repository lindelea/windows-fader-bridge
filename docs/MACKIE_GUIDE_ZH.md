# Windows Fader Bridge for Mackie Control — 中文研究版指南

当前应用版本：**v1.0.0**。

## 日常界面（2026-08-30 更新）

程序默认打开日常工作区。旧调试界面只供开发者通过启动参数 `--diagnostics` 使用，
日常界面不提供入口；**设置 → 高级**保留“打开日志目录”。

- **通道总览**：查看在线通道、真实音量与峰值、当前选择、默认设备和播放信息。
- **设置 → 通用**：立即切换中文 / English；设置关闭到托盘和随 Windows 启动。
  开机启动是可选项；是否自动连接由每台设备自己的开关控制，默认开启。
- **设备**：使用 **＋ 添加设备**管理多台控制器，各自配置 MIDI 输入/输出、设备配置、
  自动连接、触摸保护、LCD 和峰值表反馈。未保存端口的设备不会自行猜测连接。
- **按键分配**：先选已有按键，或点击“识别设备按键”后按实物键；右侧可用中英文
  搜索命令、按分类筛选和查看说明。点击“应用分配”保存，覆盖旧命令会先确认。
- **旋钮分配 / Jog 与方向**：使用同一个命令浏览器，为每个方向或按下动作独立分配。
- **编辑时所选设备不会执行自定义命令**，其他设备继续工作；返回通道总览后再测试。
  Navi / Focus 保持原机语义。命令的中文名称、分类和用途说明均保留。

窗口关闭到托盘后，可双击托盘图标重新打开；彻底退出请使用托盘菜单“退出”。
下文原有诊断界面操作仍可用于排查问题。设计与实现说明见 [日常界面](MACKIE_DESKTOP_UI.md)。

这是独立的 **Mackie Control / MCU 版**，不是 P1-Nano 专用驱动，也不是
EUCON 版的替代更新。P1-Nano 是首个计划验证的设备，其他采用标准 MCU
报文的设备使用同一个协议核心。

目前已完成协议与配置测试、真实 Windows 音频会话测试，并经过 P1-Nano 的
多轮实机操作验证。其他 MCU 型号、多台实体设备同时工作及不同固件组合仍待验证；
能够打开 MIDI 端口，不等于该设备的电机、屏幕和所有按键都已兼容。

## 1. 要安装什么？

使用环境：Windows 11 x64、控制器处于 MCU 模式、可用的 MIDI 输入和输出。
构建需要 Visual Studio 2022 的 C++ v143 工具链与 Windows SDK。
Mackie 版不需要 Avid SDK、EuControl、NAudio、虚拟 MIDI 线或第三方 MIDI 库。
运行编译好的程序还需要 Microsoft Visual C++ x64 运行库；开发机已具备。

本次开发机器已具备编译环境，Windows 也已识别 P1-Nano 的四组 MIDI 端口，
iMAP 已安装，因此**暂时不需要安装新软件**。官方手册和备用安装 ZIP
保存在本机 Documents 下的 `Windows Fader Bridge Private Research/Mackie Control`，
没有运行安装包、刷新固件或修改设备设置。

其他设备是否需要厂商 USB 驱动，按该设备官方说明操作。不要把本机
P1-Nano 的安装情况套用到所有 MCU 控制器上。

## 2. 构建和启动

在仓库目录执行：

```powershell
.\scripts\build-mackie.ps1
```

生成：`artifacts\mackie\Release\WindowsFaderBridge.Mackie.exe`。
双击启动。这是独立进程、独立托盘、独立配置，不会停止现有 EUCON 版。

首次使用需要明确选择输入/输出并保存。此后默认自动连接保存的端口，
连接成功后电机和灯光会同步 Windows 状态。名称重复或端口不匹配时不会猜测连接。

1. 控制器选择 MCU / Mackie Control 模式，不是 HUI。
2. 在“设备”选择对应的 MIDI 输入、输出；输入是设备发给电脑，输出是电脑发给设备。
3. 普通设备保留“通用 Mackie Control”。P1-Nano 可选其配置项；两者使用同一套报文。
4. 保留“触摸保护”，点击“保存”。自动模式会连接；手动模式需要点击“连接设备”。
5. 关闭窗口会隐藏到托盘；真正退出请点“退出”或托盘菜单里的退出。

不要让 DAW 和本程序同时争用同一对控制端口。不确定某个端口用途时，不要连接。

### 多台设备

点击 **＋ 添加设备**，为新设备选择独立的 MIDI 输入/输出，也可填写自定义名称。
最多可保存 16 台独立 MCU 主控制器，不允许复用另一台已配置设备的端口。
各设备的按键、旋钮、Jog 分配和连接开关分别保存，翻页和当前选择也互不干扰；
它们控制的是同一份 Windows 音频状态。总览和分配页顶部可切换当前编辑的设备，
切换不会断开其他设备。移除设备不会删除其配置备份，也不影响其他设备连接。

自动模式下拔插设备会尝试重新连接原来的端口；**主动点击“断开”后，本次运行不会
立即自动连回**。再次连接、重新开启自动连接、保存设备配置或重启程序后恢复自动尝试。
关闭自动连接不会中断正在工作的连接。手动模式下重启或拔插后需要自己点击连接。
同名端口不能唯一识别时不会自动连接，需要先解决设备命名冲突。
这不是 MCU Extender 拼接；第二台实体控制器的同时运行仍需要进一步实机验证。

## 3. P1-Nano 特别说明

P1-Nano 的单根物理推子代表 8 个虚拟通道及 Master，不能理解成软件只能
控制一个应用。控制器自身的通道选择与本程序的 MCU 分页共同决定目标。

| 设备上的 DAW 层 | 输入 | 输出 |
| --- | --- | --- |
| DAW 1 | `iCON P1-Nano` | `iCON P1-Nano` |
| DAW 2 | `MIDIIN2 (iCON P1-Nano)` | `MIDIOUT2 (iCON P1-Nano)` |
| DAW 3 | `MIDIIN3 (iCON P1-Nano)` | `MIDIOUT3 (iCON P1-Nano)` |
| 第 4 组端口 | iMAP / 维护用途 | 本程序拒绝连接 |

名称以 Windows 实际显示为准；括号外程序添加的数字只是本次枚举编号，
不会被当作设备身份永久依赖。端口编号、名字可能随驱动、固件变化。

请先在 iMAP 保存自己的配置，再选择适合 MCU 的 DAW 模式，例如官方手册
所列 Cubase / Bitwig 工作流。不要为试验覆盖已有自定义页面。
如需 iMAP 转发触摸屏映射，应先连接控制器并启动 iMAP，再启动本程序。

官方固件说明提到 1.24 修复过“选中通道和推子对应不一致”。本次**没有核实
你机器的固件版本，也没有升级**；如果后续发生类似问题，再查看版本。
不要只从 USB 名字推断固件版本。

依据：[P1-Nano 官方说明书](https://s3.amazonaws.com/assets.iconproaudio.com/wp-content/uploads/2023/07/01050723/P1Nano-PD3V102-English.pdf)，
[官方固件记录](https://s3.amazonaws.com/assets.iconproaudio.com/wp-content/uploads/2023/07/10071915/P1-Nano-Firmware-Release-Notes-4.html)。

## 4. 默认控制逻辑

| MCU 控件 | Windows 行为 |
| --- | --- |
| 通道推子 | 当前应用或音频设备的音量 |
| Master 推子 | 当前系统默认输出的音量 |
| 旋钮 1 | 当前通道音量，每格 1%；按下不执行，避免意外跳到满音量 |
| 旋钮 2 | 当前通道 Pan / Balance，每格 2%；不支持平衡时无动作 |
| 按下旋钮 2 | 当前通道 Pan 回到 Center |
| 旋钮 3–8 | 左转、右转、按下分别自由分配；默认不分配 |
| Track / Pan / Flip 分配键 | 不改变上述职责，不交换推子和旋钮 |
| Mute | 切换当前通道静音，LED 跟随 Windows |
| Solo | 仅应用通道：使其他应用静音；再按恢复 |
| 全局 Solo / Clear Solo 命令 | 清除本程序管理的 Solo，恢复之前的静音状态 |
| Rec | 仅设备通道：选择为对应的默认输入或输出，不是录音开关 |
| Rec LED | 该设备确实是默认设备才亮 |
| Select | 收到选择即选中通道；完整按下并松开后，应用通道尝试恢复窗口并置于前台 |
| Bank 左右 | 每次翻 8 个逻辑位置 |
| Channel 左右 | 每次移动 1 个逻辑位置 |
| Play / Stop | 所选应用播放暂停 / 停止；无法停止时尝试暂停 |
| Rewind / Fast Forward | 上一首 / 下一首 |
| Jog | 左右可独立分配，默认每格前进 / 后退 1 秒；播放进度需播放器开放跳转 |
| Cycle | 播放器允许时切换循环 |

以上按标准 MCU 按键编号识别。设备印刷名称或 DAW 模板不同，实际发出的
编号也可能不同，需要对照 MIDI 日志。未对应的硬件键可以学习分配命令。
Transport Record 暂不代表 Windows 录音，不会自动开始录音。

### Jog、Move 和 Zoom

普通 **Jog 左转、右转也可以独立自定义**，在底部 **Jog 设置…** 的
**普通 Jog ←→** 行选择命令。默认仍为播放进度后退 / 前进，每格 1 秒。
左右可以选不同类型的命令，也可设为未分配。以下播放目标规则仅用于播放进度命令：
选择音频输入/输出设备时跟随 Windows 当前播放器；选择应用时控制该应用。
播放器只允许读进度时不发送跳转，窗口会说明原因。

**Navi / Focus 保持原机行为，不提供自定义入口。** Navi 的 Select / Bank
消息仍走正常选通道、翻页；Focus 自行产生的鼠标行为不叠加另一套动作。
不再提供旧版 JogNavigate、JogFocus 等软件模式命令，也不改写 iMAP 配置。

Jog / Move / Zoom 共五组、十个独立的自定义动作：

| 功能组 | 第一列 | 第二列 |
| --- | --- | --- |
| Move ↑↓ | 向上时执行 | 向下时执行 |
| Move ←→ | 向左时执行 | 向右时执行 |
| Zoom ↑↓ | 向上时执行 | 向下时执行 |
| Zoom ←→ | 向左时执行 | 向右时执行 |
| 普通 Jog ←→ | 左转时执行 | 右转时执行 |

1. 打开 **Jog 设置…**，在对应方向选择命令，可选滚轮、键盘方向键及现有 Windows 快捷命令。
2. 每组离散命令分别选择 1 / 2 / 4 / 8 格触发一次，最多每秒 10 次，不累计连发。
   普通 Jog 的播放进度命令不受这个限制，仍使用上方“播放进度每格”的秒数。
3. Move / Zoom 默认未分配；普通 Jog 默认后退 / 前进播放进度，另有这两个专用选项。
   未分配方向不做任何操作；原有自定义 Zoom 左右命令会迁移保留。
4. **保存或取消、关闭设置窗口后，再测试实际动作。** 编辑期间只显示
   “检测到 Jog / Move / Zoom 哪个方向”，不执行命令，避免修改设置时误触系统操作。
5. 主窗口会显示收到的方向、分配命令或“未分配”；发送请求不等于目标软件一定响应。

原有 MCU Cursor 上下左右和 Zoom 开关决定当前四组中的哪一组，与普通 Jog 独立。
如果重连后设备保留的模式与软件当前 Move / Zoom 层不一致，可用设置页的
**方向层校准**，选择与设备一致的 Move 或 Zoom，保存后生效。这里只同步本程序
对标准 Zoom 状态的解释和反馈，不推断或修改厂商私有模式。
标准 Cursor 方向键无 LED，不伪造方向模式灯。

旧版对 MCU Cursor 单键的直接分配迁移到 Move 的相应方向；不会自动复制到 Zoom。
旧软件 Jog 模式命令停用，普通 80 键触屏分配、旋钮 3–8 和端口设置保留。
建议在更换版本前备份设置文件。

详情见 [Jog 研究与验收记录](MACKIE_RESEARCH.md)。

### 通道与分页

停用或无法打开的端点不加入；可用但非默认的输入设备仍可显示电平。
应用和设备仍以稳定 ID 保存设置，但界面只保留在线通道：下线会自动删除空位，
后续通道向前补齐；重新上线的通道追加到末尾。超过 8 个位置可翻页；窗口列表可滚动查看全部。
当前音频层上限是 128 个同时存在的音频槽位，不是某台设备的推子数量。

历史离线空位会在第一个有效音频快照到达后自动清理，不需要手动操作。
输入设备成为默认设备只改变 LED，不交换通道。
Master 的专用推子跟随默认输出；设备原有逻辑通道仍留在原位。

### 触摸保护

触摸推子期间不向该电机发送位置，也不允许切页或改变选中通道。应用或设备
此时若上下线，软件暂缓重新排位；最后一根推子松手后再一次性补齐。默认忽略没有触摸消息的推子输入，以防电机
反馈被误认为人手输入。

只有确认设备没有触摸消息、且不会回传电机动作时，才关闭“触摸保护”。
关闭后抗反馈能力降低，出现抖动应立即断开；不要直接给所有设备关闭。

### 当前通道旋钮与自由分配

八个旋钮不再分别对应八条轨道。**1 音量、2 Pan 始终指向同一个当前通道**，
主窗口右上方的“旋钮目标”和列表选中行显示其完整名称。
通过硬件 Select、点击软件通道行，或触摸目标推子来选择。触摸本身不弹出应用窗口。
收到 MCU Bank / Channel 翻页消息时，目标跟随原选中条带在新页的位置；最后一页
不足八条时选择最后一条在线通道。离线自动整理仍按稳定身份跟随。

多根推子同时触摸时，以第一根触摸确立的旋钮目标为准，全部松手后才允许重新选择。
若目标此时离线，音量/Pan 不会跳去控制替补通道。关闭触摸保护时，有效推子移动
也可确立目标。P1-Nano 的 ▲▼ 可能只切换设备本地显示：没有可识别的 MIDI 选择消息，
程序就不能推断它的目标；可轻触对应推子确认，以软件“旋钮目标”为准。

点击主窗口左下角 **“旋钮 3–8 分配…”**，每一行设置三个独立动作：

- **当前通道**：音量、Pan、静音、Solo、默认设备、窗口置前、媒体播放/切歌/进度。
  应用专属动作不用于音频设备；播放器仍须提供相应控制能力。此处的媒体命令
  不使用全局媒体键后备路径，不支持时不会误控另一个播放器。
- **其余分类**：Windows / 音频命令。窗口/编辑命令作用于前台窗口，系统命令
  作用于系统，不会因为旋钮服务当前通道就自动转给那个应用。
- 可选“未分配”，只使用其中一个动作；例如仅使用按下而不使用旋转。

例如旋钮 3 左转“当前通道 · 上一首”、右转“下一首”、按下“播放/暂停”；
旋钮 4 左转 `Zoom Out`、右转 `Zoom In`、按下 `Reset Zoom`。
这是示例，不会自动替用户分配。保存后立即生效、重启保留；取消不更改，清空也须保存。
已有 80 个触屏按键分配保持不变，无需重新导入 iMAP。

旋钮 1/2 连续调节保持相对增量；3–8 为命令式旋转，每条旋转消息执行一次（不按加速
值连发几十次），每个旋钮最多每秒 10 次，超出丢弃。按下须松开后才能再次触发。
设置窗口打开期间八个旋钮暂停执行，推子、触摸和音频反馈仍工作。
光环 1 显示当前音量、2 显示当前 Pan，3–8 不伪造参数值；原有通道 LCD 名称和峰值
仍按条带显示，不改成设备专用插件页面。

### 显示、媒体和高级音频

- Windows 窗口保留完整中文名称；标准 MCU LCD 只能显示短 ASCII 文本，
  当前每个通道 6 个字符加间隔，不能承诺中文或自定义字体。
- 峰值取 Windows 实际音频通道的最大值，转换成 MCU 的 13 档显示。
  不等同于 EUCON 的分声道立体声峰值表，也不是插值真峰值检测。
- MCU 标准反馈不等于每台设备都会自动启用电平显示。厂商特有的显示初始化、
  RGB、D5 和触摸屏文字暂不发送，不能把“TX 增加”当成屏幕已验证。
- 选中应用后，窗口显示其可读取的歌曲名、艺术家、进度和播放状态。
  只能读进度但不能拖动的应用显示“只读”。不提供能力的动作不会伪造成功。
- 播放时，时间显示屏输出所控制播放器的已播放时间 `HH.MM.SS`；Windows 窗口
  同时显示 `已播放 / 总时长`，方便核对。先选中 Apple Music 等应用通道，
  暂停、切歌或拖动后检查两边是否同步。选中输出 / 输入设备或没有所选通道时，
  跟随 Windows 当前播放器，不再要求先选一次应用通道。选中应用时仍只匹配该应用。
  Jog 分配为播放进度命令时，只在播放器开放播放进度调整时工作；没有播放器、进度只读或无法发出请求时，
  窗口媒体区域会显示原因，不再把错误提示隐藏起来。
- 暂停后保留歌曲进度 10 秒，再显示电脑本地系统时间（24 小时制 `HH.MM.SS`）。
  启动后没有媒体、或播放器不提供可读进度时，直接显示系统时间。恢复播放、
  切歌或检测到实际进度调整时，立即切回歌曲进度；暂停中调整后重新保留 10 秒。
  窗口标明数字屏当前的时间来源。系统时间每秒变化，跟随电脑校时和时区；
  暂停倒计时不受系统时钟调整影响，也不改变播放按钮的 LED 状态。
- 时间读取不要求播放器允许拖动进度。不提供有效时间范围时显示系统时间；
  播放器未报告速率时只显示它实际上报的位置，不猜测播放速度。时间显示是
  整秒歌曲进度，不是专业帧同步，也不会猜歌曲 BPM 或小节数。
  此反馈走通用数字显示 CC；P1-Nano 和其他 MCU 设备仍需分别实机确认。
- 没有媒体会话的旧播放器可尝试系统媒体键；这是全局后备路径，可能由另一个
  播放器接收，不能保证专门控制 foobar2000。
- 控制面板不再重复提供“选择、置前、Clear Solo、单声道、应用路由”等按钮；
  对应硬件语义或自由分配命令仍按需要使用。

## 5. 自由分配 Windows、音频命令

命令覆盖原有 14 个分类：音频、系统工具、设置、个人文件夹、文件管理器、窗口、
虚拟桌面、任务栏、编辑、浏览器、媒体、截图输入、输入法和辅助功能。
完整的英文名、中文解释见 [Windows 命令中文手册](WINDOWS_COMMANDS_ZH.md)。
该手册的“命令说明”通用，EuControl 分配步骤只适用于 EUCON 版。

分配方式：

1. 在本程序选分类及命令，例如 `System Tools → Task Manager`。
2. 点“学习按键”，然后按控制器上的目标按键。
3. 学习成功会列出 MIDI 通道、Note 编号和命令；**这次学习不执行命令**。
4. 松开后再次按下才执行。重复分配同一按键会替换原命令。
5. 可在列表选中一条后取消分配，恢复该按键原有的 MCU 行为。

为保护核心操作，MIDI 通道 1 的推子触摸、通道按键和分页键不能覆盖。
可学习该通道 Note 54–95、102–103 的功能键，或 MIDI 通道 2–16 的 Note 按键。
Note 96–101 保留给方向、Zoom 和原机操作，不能被通用按键分配截走。
只支持按下 / 松开式 Note；CC、只有按下没有松开的宏、QWERTY 不是这套学习输入。

`Mono Audio` 和 `Clear Solo` 的灯按实际状态显示；普通 Windows 命令的灯
随按下 / 松开，不代表目标应用的内部状态。Ctrl / Alt 等单独保持型修饰键
不是当前命令模式；组合快捷键作为一次完整命令发送。

### P1-Nano 的 80 个触摸屏位置

触摸屏的页面、标签和颜色由 iMAP 管理。本程序**不写 iCON 私有触摸屏协议**。
建议在 iMAP 中使用独立的 MIDI 通道 16，按下发 Note On，松开发 Note Off，
5 页依次使用 Note 0–79；再在本程序学习对应命令。这里的通道 16 是 MIDI
消息通道，不是 USB 第 4 端口。

提供 [80 键命令表](mackie-touchscreen-example.csv)，按“系统、窗口、文件、
媒体、编辑”五页安排。断开 MIDI 后点击 **一键应用 Windows 80 键预设**，
一次装入配套命令，无需逐个学习。它会备份旧设置，保留其他分配；若 MIDI
通道 16 / Note 0–79 已有不同命令，则整次操作取消，不覆盖自定义设置。

CSV 不是 iMAP 文件。要获得可导入的文件，使用
`scripts/make-mackie-touchscreen-preset.ps1` 转换自己的完整 iMAP 导出。
默认只改 DAW 2 的触屏区域，保留 DAW 1 / DAW 3、其他 DAW 模式和核心控件。
原始厂商配置和生成文件均不提交 Git。详见
[触屏预设中文说明及五页按键图](MACKIE_TOUCHSCREEN_ZH.md)。
其他具有 MIDI 自定义键的 MCU 设备同样可以采用这组命令，不依赖 iCON 私有协议。

QWERTY 热键也能由 iMAP 直接发给 Windows，但它们不会经过本程序的命令
学习和状态反馈，两种方式不要对同一个按键重复使用。

## 6. 配置、日志与恢复

- 配置根目录：`%LOCALAPPDATA%\Windows Fader Bridge\Mackie`；旧 `settings.txt` 保留给第一台设备，
  `workspace.txt` 保存设备列表及通用设置，新增设备分别保存在 `devices` 中。
  “打开配置目录”会打开程序实际使用的目录，包括系统重定向后的路径。
- 日志：程序旁的 `FaderBridge.trace.log`，在“高级”点击“打开日志目录”。
- “MIDI 日志”开启后记录输入、输出和错误；关闭可减少日志量。
- 配置只存端口名称、显示选项、在线通道的稳定身份顺序及命令 ID，不允许任意脚本路径。
- 端口变化或发送失败会断开；自动模式只尝试原来保存的端口，不会改连其他设备。
- 断开不会替你修改 Windows 音量，也不会自动取消其他程序设置的静音。
- 退出前有 Solo 时，建议先执行 Clear Solo。本阶段不要在 EUCON 和 Mackie
  两个进程中同时管理 Solo，它们还没有统一跨进程的 Solo 所有权。

## 7. 验证命令和实机清单

常规构建会运行纯协议 / 配置 / 身份队列测试，不打开 MIDI 或音频端口：

```powershell
.\scripts\build-mackie.ps1
```

显式运行真实音频集成测试：

```powershell
.\scripts\build-mackie.ps1 -AudioIntegration
```

它只创建并调整自身的无声、非持久化音频会话，不碰系统默认设备、Mono、
其他应用的 Solo / Mute 或硬件 MIDI。现有控制程序可能短暂看到这个测试通道。

程序还支持 `--smoke-test`：后台运行约 6 秒，读取音频和端口后退出，
MIDI 发送数必须为 0；活动音频端点不存在的机器会报告失败。

回来后的实机验证顺序：

1. 保存 iMAP 配置，确认 MCU 模式和匹配端口。
2. 先看 RX 是否随操作增加，测试一个应用推子和反向 Windows 音量。
3. 验证触摸、松手、快速反转；电机无来回争抢。
4. 验证 Select、Mute、Solo、Rec 默认输入 / 输出及 LED。
5. 开 9 个以上逻辑通道，确认翻页、退出应用、再出现后不串道。
6. 验证 Master 默认输出切换、Pan 及按下回中。
7. 检查 LCD、峰值、播放键、歌曲状态和一个学习的 Windows 命令。
8. 最后检查断线 / 重连、托盘后台、重新启动后配置恢复。

需要另一台标准 MCU 设备完成交叉验证，才能扩大“已验证兼容”名单。
目前不支持 HUI、MCU Extender 多机拼接、旧 Logic Control 型号握手、
安装器或完整通道重排 UI。多台独立主控制器与保存端口的自动连接已实现。

协议依据和未验证项详见 [研究记录](MACKIE_RESEARCH.md)。
